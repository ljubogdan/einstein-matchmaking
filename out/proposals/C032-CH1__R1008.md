# Edge-deployable unsupervised anomaly detection for Modbus and BACnet OT networks

**Company:** SecureEdge Labs [C032], Cybersecurity, 19 employees, NTP Novi Sad.  
**Faculty:** Faculty of Technical Sciences, Department of Computing and Control Engineering [R1008].  
**Format:** Contract research  
**Supervisors / contacts:** Principal Investigator / Full Professor, Department of Computing and Control Engineering (academic) and SecureEdge Labs Technical Lead (security engineering) (company)

### The problem
- The company's sensor network captures traffic across customer sites but the team has almost no labelled examples of actual attacks on these networks to train detection models, because real incidents are rare and customers refuse attack simulations on live plant. [C032-CH1]
- Hand-written rules miss slow, low-volume probing entirely, and statistical baselines drift with shift patterns and seasonal production changes, generating alert noise that analysts cannot keep up with. [C032-CH1]
- Any detection model must run inference on the edge sensor, which has 512 MB of RAM and a modest ARM core, imposing hard limits on model size and inference latency. [C032-CH1]

### Work packages
1. Can unsupervised models trained only on unlabelled Modbus and BACnet traffic reliably detect slow, low-volume probing sequences without prior knowledge of attack signatures?
2. What feature representations derived from OT protocol traffic windows best preserve anomalous sequence structure while remaining computable on a constrained ARM core?
3. How do quantisation and structured pruning affect detection sensitivity for rare anomaly classes in Modbus and BACnet traffic?
4. How can concept drift caused by scheduled production changes be distinguished from genuine anomalous activity within an online learning framework?

### Plan
| Phase | Work | Result |
|---|---|---|
| Data characterisation and baseline modelling (months 1–3) | Characterise anonymised traffic logs from all three sites, design a feature extraction pipeline compatible with the company's in-house parsers, train candidate unsupervised models, and validate detection using synthetic anomaly injection on the ICS testbed. | Baseline model prototype demonstrating anomaly detection on real traffic and testbed scenarios |
| Edge optimisation (months 4–6) | Apply weight quantisation and structured pruning to reduce model footprint and inference latency; evaluate detection performance trade-offs at each compression level against the sensor memory and cycle budget. | Edge-optimised model passing EdgeWatch RAM and latency constraints |
| Hardware integration and testing (months 7–9) | Deploy the optimised model on an EdgeWatch reference unit; integrate with in-house Modbus and BACnet parsers and sensor firmware; run end-to-end integration tests on real hardware. | Model running on EdgeWatch reference unit with measured detection and resource metrics |
| Final evaluation and deployment documentation (months 10–12) | Evaluate detection coverage across all three customer site traffic sets, refine the drift-handling mechanism, and prepare deployable model artefacts together with integration guidance and deployment documentation. | Deployable model artefacts and integration documentation ready for production rollout |
