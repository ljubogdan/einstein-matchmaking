# Catching unusual control-network traffic without attack examples

**Company:** ArmaturaSec d.o.o. [C001], Cybersecurity, 67 employees, Zrenjanin.  
**Researcher:** Krisztina Kiss, Full Professor, Faculty of Technical Sciences, Department of Computing and Control Engineering [R1008].  
**Format:** Joint project  
**Supervisors / contacts:** Full Professor, Department of Computing and Control Engineering, Faculty of Technical Sciences (academic) and Lead Engineer, ProtoSense (company)

### The problem
- Some client networks have been running for twenty years with no security monitoring at all, so if compromised they would not know whether they had been attacked. [C001-CH1]
- A classifier trained on public ICS datasets flagged so many false positives in real deployments that clients started switching the alerts off. [C001-CH1]
- The ProtoSense module needs a method that works with no attack examples and that can be explained to a plant manager in plain language. [C001-CH1]

### Work packages
1. Which statistical features of Modbus TCP and BACnet/IP traffic best characterise site-specific normal behaviour when only unlabelled captures are available?
2. How should a recalibration schedule be tuned so that a learned baseline tracks gradual shifts in normal traffic without masking real anomalies?
3. Can a one-class detection model be made compact enough to run inference on an embedded security processor without affecting packet forwarding latency?
4. What format for anomaly alerts communicates the nature of a deviation clearly to a plant manager with no security background?
