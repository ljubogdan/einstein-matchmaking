# On-Device Unsupervised Anomaly Detection for Modbus and BACnet Networks

**Company:** ArmaturaSec d.o.o. [C001], Cybersecurity, 67 employees, Zrenjanin.  
**Faculty:** Faculty of Technical Sciences, Department of Computing and Control Engineering [R1015].  
**Format:** Joint project  
**Supervisors / contacts:** Associate Professor, Department of Computing and Control Engineering (academic) and CTO / Head of Product Engineering (company)

### The problem
- No client has ever provided a packet capture containing a confirmed attack, leaving no labeled malicious traffic available for model training. [C001-CH1]
- A supervised classifier trained on public ICS datasets generated unacceptable false positives in live deployments, prompting operators to disable the alerts entirely. [C001-CH1]
- The required solution must learn site-specific normal traffic patterns without any attack examples and run inference on embedded hardware. [C001-CH1]

### Work packages
1. Can autoencoder-based models trained solely on site-specific Modbus TCP and BACnet/IP traffic reliably detect anomalies without any labeled attack examples?
2. What feature encoding strategies and traffic window configurations best preserve detection sensitivity after model compression for embedded deployment?
3. How should a site-specific baseline model adapt over time to accommodate legitimate changes in industrial network behaviour without accumulating false negatives?
4. What memory and latency constraints does the target embedded hardware impose, and how do these bounds shape viable model architectures?

### Plan
| Phase | Work | Result |
|---|---|---|
| Phase 1 – Algorithm Design and Offline Validation (M1–M6) | Design and compare unsupervised anomaly detection architectures for Modbus TCP and BACnet/IP traffic; evaluate candidates on archived traffic captures provided under NDA, measuring detection rate and false-positive rate. | Baseline algorithm prototype validated on archived traffic, with documented performance metrics across representative traffic profiles. |
| Phase 2 – Model Compression and On-Device Benchmarking (M7–M12) | Apply quantisation, pruning, and knowledge distillation to compress the selected model; deploy on the ProtoSense hardware bench and measure inference latency, memory footprint, and impact on packet forwarding. | On-device implementation with latency and resource benchmarks demonstrating feasibility for embedded deployment. |
