# Detecting unusual network behaviour on industrial sensors without labeled attack examples

**Company:** SecureEdge Labs [C032], Cybersecurity, 19 employees, NTP Novi Sad.  
**Researcher:** Vuk Đukić, Associate Professor, Faculty of Technical Sciences, Department of Computing and Control Engineering [R1015].  
**Format:** Joint project  
**Supervisors / contacts:** Associate Professor, Department of Computing and Control Engineering (academic) and Security Engineering Lead (company)

### The problem
- The company needs to detect unusual behaviour on Modbus and BACnet networks without labelled attack data. [C032-CH1]
- Hand-written rules miss slow, low-volume probing entirely, and statistical baselines drift with shift patterns and seasonal production changes, generating noise that analysts cannot keep up with. [C032-CH1]
- Any detection model must run inference on the edge sensor, which has 512 MB of RAM and a modest ARM core, and must be deployable within twelve months. [C032-CH1]

### Work packages
1. Can autoencoder models trained solely on unlabelled Modbus traffic detect the anomalous sequences that hand-written rules and statistical baselining miss?
2. Can anomaly detection models be compressed and quantized to run inference within the memory and compute limits of an ARM-based edge sensor?
3. How can incremental or federated learning mechanisms keep detection models current as production baselines shift across multiple customer sites?
4. Can a model architecture developed for Modbus traffic be extended to cover BACnet traffic with comparable detection performance?

### Plan
| Phase | Work | Result |
|---|---|---|
| Data preparation and baseline model training (Months 1–3) | Extract protocol features from anonymised Modbus packet logs and train an autoencoder model on unlabelled traffic to learn patterns of normal operation, then evaluate on held-out benign traffic. | Baseline anomaly detection model trained on anonymised Modbus logs and evaluated on held-out benign traffic. |
| Edge hardware optimisation (Months 4–6) | Apply model compression and quantization to reduce the model footprint to fit within the edge sensor memory and ARM compute constraints, then validate inference on representative test hardware. | Edge-feasible model variant validated on ARM-constrained test hardware meeting RAM and compute limits. |
| BACnet extension and drift handling (Months 7–9) | Extend the feature extraction pipeline to BACnet protocol traffic and design an incremental or federated learning mechanism to keep models current as production baselines shift across sites, addressing the third and fourth research questions. | BACnet protocol extension and federated or incremental learning mechanism evaluated on multi-site traffic. |
| Integration and reporting (Months 10–12) | Integrate validated models into the edge sensor firmware environment, produce integration documentation, and compile a performance report covering all evaluation results. | Final models, integration documentation, and performance report delivered. |
